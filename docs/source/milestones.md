## Tasks Before setting up Shelly

### 1. Website + Backend Skeleton

- Create one GitHub repository for the project.
- Build the website using **React (or any other libraries)**
- Build the backend using **Python + FastAPI**.
- Create the basic pages: Login, Dashboard, Appliances, Calibration and Settings.
- Create the basic backend structure and API.
- Divide the work between the 2 people: one mainly handles backend, database and MQTT; the other mainly handles the website.
- Agree on the API structure so the website and backend can work together.

### 2. Database

- Use **PostgreSQL**.
- Create tables for Users, Devices, Appliances, Electricity Readings, Calibration Sessions and Predictions.
- Use **SQLAlchemy** to connect FastAPI with PostgreSQL.
- Test saving and retrieving data from the database.

### 3. Website ↔ Backend Working

- Connect the React website to the FastAPI backend using REST APIs.
- Test login, adding appliances and getting appliance information.
- Create APIs for current power, historical readings and calibration.
- Make sure information entered on the website is saved in the database and can be displayed again.

### 4. Fake Electricity Data

- Create a Python program that generates fake electricity readings because we don't have the Shelly connected yet.
- Simulate values such as voltage, current, power and timestamps.
- Create different patterns for appliances such as kettle, microwave, refrigerator and washing machine.
- Send the fake data to the backend and store it in PostgreSQL.
- Display the fake electricity data on the website using graphs.

### 5. Calibration System Working With Fake Data

- Customer selects an appliance, for example "Kettle."
- Website tells the customer to turn the appliance OFF and then ON.
- Backend records the electricity data during the calibration.
- Detect the power change when the appliance turns ON and OFF.
- Save the complete power pattern, not just the wattage.
- Repeat the calibration 3–5 times to get multiple examples.(there would be an option to do this)
- Store the calibration data in the database.
- Make the website show when calibration is completed.
- The calibration system should eventually capture features such as power, duration, energy, rise/fall time and changes in power.

### 6. Mosquitto + Python MQTT Working

- Install **Mosquitto MQTT broker**.
- Learn and test basic MQTT publish/subscribe.
- Use **Paho MQTT** in Python.
- Create a test Python publisher that behaves like the Shelly.
- Create a Python subscriber that receives the MQTT data.
- Connect MQTT data to our backend.
- Test the complete pipeline before having the real Shelly:

**Fake Data → MQTT → Mosquitto → Python → Backend → PostgreSQL → Website**

## After Installing Shelly

### 1. Shelly Installed and Sending Real Data

- Have the **Shelly EM Gen3** installed
- Connect the Shelly to Wi-Fi.
- Configure the Shelly's MQTT connection.
- Connect it to our Mosquitto broker.
- Identify and test the Shelly's MQTT topics and data.
- Check that we are receiving real voltage, current, power and energy readings.

### 2. Real Data Stored and Displayed

- Replace the fake data generator with the real Shelly data.
- Build the pipeline:

**Shelly → MQTT → Mosquitto → Python → Backend → PostgreSQL**

- Store the real readings with timestamps.
- Check and clean invalid or missing data.
- Display live power, voltage, current and energy on the website.
- Add historical graphs.
- Collect enough real household data to analyse normal electricity patterns.

### 3. Appliance Calibration + First ML Model

- Use the website to calibrate real appliances.
- Collect several calibration sessions for each appliance.
- Clean and process the electricity data using **Pandas and NumPy**.
- Detect ON/OFF events and changes in power.
- Extract features such as power level, duration, energy, rise/fall time and power transitions.
- Start with simple ML methods such as **K-Means/DBSCAN clustering and Random Forest classification**.
- Create a personalised appliance profile/model for each customer.
- Test whether the model can recognise appliances that were calibrated.

### 4. Multiple-Appliance Detection + Continuous Learning

- Test situations where two or more appliances are running at the same time.
- Learn how to separate overlapping electricity patterns.
- Handle appliances with multiple power levels, such as washing machines.
- Give predictions with confidence scores.
- Example: **"Kettle ON — 92% confidence."**
- Allow the customer to confirm whether the prediction is correct.
- Save customer confirmations as additional training data.
- Continuously improve the personalised model using new data.
- Eventually make the system recognise multiple appliances from the total household electricity signal.

**Final system:**

**Shelly EM Gen3 → MQTT → Mosquitto → Python Backend → PostgreSQL → ML Model → Website/Dashboard**

The main idea is to first build and test the **whole software system using fake data**, and only then connect the real Shelly. This means the Shelly will become our real data source instead of being something that blocks our development.
